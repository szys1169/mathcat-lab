# 组织、写作与论文合并

## 组织方式

- **历史时间线（默认）**：提出来源、早期特例、推广和近期进展。
- **方法流派**：按技术路线分组，说明其适用范围和与本文方法的关系。
- **结果对比**：比较界、维数、系数域、假设或结论强度。
- **Gap 定位**：从有证据的未覆盖范围过渡到本文贡献。

通常以时间线为主干，在最接近工作处切换到结果/方法对比，最后用审计后的 gap 表述定位本文。避免逐篇罗列摘要。

## 两种正文

`related-work.tex` 是可独立成节的版本；`related-work-inline.tex` 是引言中 2–4 段的压缩版本。两者必须使用同一论断台账和 BibTeX，不得出现互相矛盾的范围或开放状态。

已有工作使用明确归因：“由 X 证明”“X 将其推广到……”“在假设 H 下，X 得到……”。首次承担载荷时引用；之后避免机械重复引用。本文结果只按贡献画像陈述，不由此 Skill 扩充数学含义。

## 高风险措辞

以下词语需要 `verified_gap` 或同等强证据：首次、唯一、完全解决、最优、最强、此前无人研究。证据不足时改为：

- “据本文采用的检索范围，我们尚未发现……”；
- “现有来源主要处理……，而本文关注……”；
- “这表明一个尚待进一步核验的差异……”；
- “与 X 的结果相比，本文在已列明的假设下处理……”。

## BibTeX

优先正式发表版本；若只有预印本，准确标记。合并时按 DOI 去重，再检查 key 冲突。不要静默覆盖同 key 的不同条目，也不要凭记忆补全缺字段。

## 合并到论文

默认只生成片段和预览，不修改用户稿件。用户明确要求合并时：

1. 复制到新的版本目录；
2. 识别目标章节、宏包和引用命令；
3. 合并 `.bib`，冲突时停止；
4. 插入独立节或内联段落；
5. 编译并生成 `integration.diff`；
6. 原稿保持不变。

目标期刊模板和用户现有风格优先于本 Skill 的默认排版。
