# Repair and accumulated experience

State the smallest unresolved inference with its exact assumptions and successful preceding steps. Use a targeted repair: a weaker intermediate statement, a missing condition, a different proof mechanism, source lookup, or an independent partner attempt. Do not restart a comprehensive planning pipeline merely because a gap was found.

Remember `attempted_method`, `exact_obstruction`, `failure_kind`, `explored_scope` and `reopen_condition`. Distinguish refuted claim, invalid proof, unavailable material, resource limit and not-yet-solved. A new condition or lemma can legitimately reopen an old failed approach.

For revision, preserve the original candidate ID and explain how each numbered review issue was handled. Do not mark an issue fixed just because text changed. Resubmit a new proof snapshot, including any remaining conditional premises. If reviewers disagree, preserve both findings and resolve the mathematics; never repeatedly resubmit an unchanged proof until a pass appears.
