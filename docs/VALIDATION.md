## 已有真实运行

以猜想 3.6 为案例，使用本机 Astra / medium 完成普通讨论、文献调研、相关工作、论文写作、论文修改审查和 PPT 功能流程。中英文论文各 5 页，中文 PPT 共 18 页；这些是流程产出，不是重新证明猜想的认证。

自动安排与人工批准两种研究模式分别按约 15 分钟预算检查流程。覆盖暂停/恢复、一次焦点安排批准、一次无效等待方案退回和阶段报告交付。两次补测均在第二次审查完成前到达时限，不能记为解决猜想。首次搜索事件解析失败及后续修复记录保存在开发环境中，没有抹去失败历史。

## 尚未充分覆盖

复杂伙伴新增/改派的完整真实审批、长周期顾问、复杂证明依赖图、真实失败后的局部交付重试、崩溃恢复以及跨题型研究效果，仍需更多实测。最近两次研究补测没有创建伙伴猫，顾问周期也没有触发。

历史整套 Node 回归中仍有旧默认值、旧能力与旧界面断言需要适配，本次没有把它们全部重跑成通过。仓库保留测试，不能将定向回归通过描述为所有测试均通过。

真实对话、论文、来源 PDF、日志和带本机路径的测试回执不进入公开源码仓库。此页提供人工整理的检查范围，不冒充原始自动验收回执。

`scripts/run-validation.mjs` 提供按名称选择的离线检查，输出保存在忽略的 `tests/results/`。完整 Rust 测试可运行 `cargo test --workspace`，构建可运行 `cargo build --release --bin mathcat-v2`；完整平台回归可运行 `npm test`。按需要选择范围，不会通过该脚本自行启动付费数学研究。
