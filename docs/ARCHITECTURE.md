# 当前 demo 架构

浏览器与 Node 平台负责对话、工作区、能力选择、研究白板、模型设置及成果交付。平台通过本地研究 API 连接 Rust `mathcat-v2`；Rust 管理研究轮次、角色会话、控制消息、候选审查和持久化。模型执行依赖本机 Codex。

领研猫在研究与整体安排之间循环，保留研究判断和组织权。伙伴猫具有研究能力，在任务范围内自主选择方法并在交接点报告。没有另设一个独立调度规划猫。

审核猫检查候选成果；顾问猫周期性审视路线与重复尝试；展示猫整理白板摘要；记忆猫整理成果和后续恢复所需线索。辅助摘要不能继承原成果的数学可信保证。

SQLite 与文件证据共同保存题目版本、调用记录、控制回执、不可变候选、来源及审查状态。提交候选时冻结精确题面及选定题面来源；这些是未审核输入，不能自动成为已证明引理。非平凡前提仍需要精确读取和申报。正式事实只能由受控准入流程写入。

人工模式在数学动作成功处理后才生成待批准的分工；等待必须对应真实待处理工作。当前错误与历史错误分开保存，执行完成、候选通过、问题解决和交付完成分别表示不同状态。

论文写作消费已有材料，由独立写作适配器组织中文、英文及编译检查。项目级暂停同时约束研究与交付，已有成果可继续浏览。平台目前面向本地单人使用，多租户部署与账号隔离不在本 demo 范围。

后端还保留历史模块与相应测试；不能据其存在断言当前 `mathcat-v2` 已提供所有历史实验能力，尤其不能把自然语言审查称为形式化验证。
